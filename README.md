# VIBE-YOUTUBE

Исследование и запуск масштабируемого AI-assisted YouTube-медиа.

## Документация

Каждый тип информации имеет одного владельца:

1. [`docs/CONTEXT.md`](docs/CONTEXT.md) — цель, ресурсы, ограничения и текущий этап.
2. [`docs/PLAYBOOK.md`](docs/PLAYBOOK.md) — аудитория, позиционирование, контентная и производственная система.
3. [`docs/EXPERIMENTS.md`](docs/EXPERIMENTS.md) — гипотезы, конкретные видео, упаковка, метрики и результаты.
4. [`docs/SOURCES.md`](docs/SOURCES.md) — источники и область их применения.
5. [`docs/SCRIPT.md`](docs/SCRIPT.md) — зафиксированный публичный сценарий VIDEO-001.
6. [`docs/STORYBOARD.md`](docs/STORYBOARD.md) — раскадровка, asset plan и production gates VIDEO-001.
7. [`archive/`](archive/) — исторические материалы, не являющиеся текущим контекстом.

Информация подробно хранится только в файле-владельце. В остальных файлах допустимы только ссылки без пересказа.

## Рабочая среда

Текущая локальная среда проекта:

- shell: Git Bash;
- repository: `~/projects/vibe-youtube`;
- общение и инструкции: русский;
- внутренняя документация и описания тестов: русский;
- channel-facing content, scripts и generation prompts: английский;
- создание файлов: `cat > file <<'EOF'`;
- изменение существующих файлов: Python scripts;
- ignore rules: только корневой `.gitignore`;
- PowerShell не используется без прямого запроса;
- команды должны быть короткими, проверяемыми и не закрывать shell.

## Синхронизация

Между сжатиями диалога достаточно проверить существование указанного commit без полного перечитывания репозитория.

Полная синхронизация выполняется:

1. по прямой команде пользователя;
2. после сжатия диалога, когда пользователь сообщает об этом;
3. когда задачу невозможно безопасно выполнить без перечитывания актуального файла-владельца.

При точечной задаче открывается только соответствующий файл-владелец.

Полная синхронизация включает:

1. проверку commit;
2. чтение `CONTEXT.md`;
3. чтение файла-владельца текущей задачи;
4. проверку связанных manifests и активного production-кода;
5. перепроверку изменяемых внешних фактов при необходимости.

## Безопасность

В публичный репозиторий запрещено коммитить ключи, токены, cookies, session data, платёжные реквизиты, KYC-документы, приватные договоры, персональные данные партнёров и credentials.
